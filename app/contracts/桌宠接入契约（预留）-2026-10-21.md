# 桌宠接入契约（预留）· 2026-10-21

> **这是什么**：用户决定把「桌宠」做成**独立项目**（自己开发），本仓（林离的信）
> **不实现宠物本体**，只预留一个**只读接入接口**。等独立项目做好后，按本契约接进来即可。
> 本文就是那份"接口"，不是功能说明。

---

## 1. 边界（先划清，免得做着做着跑偏）

| 谁做什么 | 内容 |
|---|---|
| **本仓（林离的信）负责** | 提供一个**只读状态接口** `GET /api/pet/state`；外壳负责启动桌宠进程、把 `base` 与 `token` 传过去 |
| **独立桌宠项目负责** | 宠物窗口本体（透明置顶、拖拽、点击互动、动画/表情）、按状态渲染、把互动事件处理在自己那边 |
| **两边都不做** | 云同步、上传、任何外联；宠物不得把用户数据发出去 |

**红线（硬）**：桌宠进程**只能连本机回环**（`127.0.0.1`），不得新增任何外部网络请求、不得上传文件或信件内容。与主程序一致：唯一外联＝用户自填的官方 Key，其它一律本机。

---

## 2. 状态接口（本仓已实现）

`GET /api/pet/state`　（需带 `X-Linli-Token` 头，见 §4）

返回一帧只读快照（JSON）：

```json
{
  "version": 1,
  "tod": "TOD12",          // 时段键：TOD12 / TOD1730 / TOD2000
  "slot": "1200",          // 时段片名部分：1200 / 1730 / 2000
  "scene": "A",            // 场景：A / B / C
  "state": "idle",         // 待机状态
  "label": "白天",          // 时段中文名，可直接显示
  "hasAssets": true,       // 本期是否装了待机素材
  "unread": 2,             // 她写来、你还没读的信件数
  "now": "2026-10-21T06:12:00.000Z"
}
```

- **只读**：不接受任何写操作；桌宠改了什么都别指望它落库。
- **轮询建议**：30–60 秒一次即可（与前端 `/api/idle/next` 同节奏）。时段本来按本机时钟走，不必高频拉。
- **数据源**：复用主程序现成的 `idleNext()`（时段/场景/状态都由落库种子钉住），不另算一套，避免两边对不上。

> 说明：`state` 字段在契约 schema 里统一填 `available`（桌宠接入是"读就绪"，不是"未实现"）。
> "预留"是**产品层面**的说法，写在本文，不进 schema 枚举。

---

## 3. 启动 / 连接契约（外壳侧，待接）

独立桌宠进程由**主程序外壳**（`src/LinliShell`）启动，启动时把两项信息交给宠物：

| 变量 / 参数 | 值 | 用途 |
|---|---|---|
| `LINLI_API_BASE` | `http://127.0.0.1:<实际端口>` | 宠物拼 `/api/pet/state` |
| `LINLI_API_TOKEN` | 会话令牌 | 放进请求头 `X-Linli-Token` |
| `LINLI_PET_HOME`（可选） | 宠物自己的数据目录 | 宠物存自己的配置/缓存，别写进主程序目录 |

- 端口是**动态**的（主程序启动时选），所以**必须由外壳在启动时传入**，宠物不能写死。
- 外壳里的启动接入点：`src/LinliShell`（**待接**——等独立项目做好后再动，不在本仓预先写空壳）；宠物路径从设置里读，未配置就不启动。
- 宠物是**独立透明置顶窗口**，建议复用主程序已有的置顶/透明/圆钮那套做法（`WallpaperHost.cs` / `DesktopDock.cs`）的**思路**，不共享进程。

---

## 4. 认证

- 与其它 `/api/*` 相同：请求头 `X-Linli-Token: <token>`。
- token 由外壳启动宠物时传入（`LINLI_API_TOKEN`），宠物**只存在内存**，不落盘明文。
- 不带 token ⇒ 401。

## 5. 事件回传（**暂不实现，留白**）

如果将来宠物需要"点一下林离，主程序要有反应"（比如打开信箱），再在**本仓**加一条写接口，
例如 `POST /api/pet/event { type }`，**仍然只在本机回环、带 token**。
现在**不预留空壳接口**（避免死代码）；到真需要时按现有写接口的模式加，并补护栏与契约登记。
在此之前，宠物侧的交互尽量**自洽**（自己播动画、自己弹气泡），不回写主程序。

---

## 6. 独立项目做好后，接入的步骤

1. 把宠物程序路径填进主程序设置（接口已留，字段待接）；
2. 外壳按 §3 启动宠物并传 `base`/`token`；
3. 宠物按 §2 拉状态、按状态渲染；
4. 联调只在本机回环；上线前过一遍红线自检（无外联、无上传）。
